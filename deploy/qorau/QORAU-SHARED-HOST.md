# Соседние проекты на сервере qorau (192.168.1.5)

Инструкция для того, кто ставит на эту машину другой проект (первый такой —
магазин **dos-mart.kz**). Машина принадлежит MDM-стеку Qorau, он на ней
главный и уже в пилоте у заказчика (466 планшетов). Всё ниже — чтобы соседний
проект не сломал MDM и не выпал при его обновлении. Схема и её устройство со
стороны MDM — `docs/INSTALL-ON-PREM.md` §3.6.

## 1. Как устроена машина

```
прокси заказчика (TLS, DNS, сертификаты всех доменов, 192.168.1.3)
        │ http + X-Forwarded-Proto: https
        ▼
192.168.1.5:80  edge_nginx  (/opt/edge, маршрутизация по имени домена)
        ├─ qorau.soilephone.kz → 127.0.0.1:8080  (MDM, /opt/mdm)
        ├─ dos-mart.kz         → 127.0.0.1:8088  (магазин, /opt/dosmart)
        └─ любое другое имя    → 404
```

| Что | Где |
|---|---|
| Edge | `/opt/edge`: `compose.yml`, `nginx.conf`, **`sites.d/` — один файл на проект**; контейнер `edge_nginx`, порт 80 хоста |
| MDM | `/opt/mdm`, контейнеры `mdm_*`, сеть `mdm_default`, порты 443 (прямой доступ, свой CA) и 127.0.0.1:8080 |
| dos-mart | `/opt/dosmart`, compose-проект `dosmart`, порт 127.0.0.1:8088 |
| Файрвол | ufw: 22 только из Tailscale, 80/443 всем. Опубликованные Docker-порты ufw обходят, поэтому проекты публикуются на 127.0.0.1 |
| Ресурсы | 4 ядра, 9,4 ГБ RAM (MDM ограничен ~3,2 ГБ), диск 122 ГБ, свободно ~100 ГБ |
| Пользователи | `ubuntu` (sudo, docker), `mdm` (владелец `/opt/mdm`, docker). Вход только по ssh-ключу |

`/opt/mdm/nginx.conf` и `compose.yml` перезаписываются при каждом обновлении
MDM — ничего туда не дописывать. Всё чужое живёт в `/opt/edge/sites.d/` и в
каталоге самого проекта.

## 2. Куда класть проект

- Каталог `/opt/<проект>`. Не `/home/ubuntu`, не `/opt/mdm`.
- Свой compose-проект (`name:` в файле), свои сети. **К `mdm_default` и сетям
  других проектов не подключаться** — из `mdm_default` видны Postgres и Redis MDM.
- Свой Postgres в своём контейнере, порт наружу не публиковать.
- Лимиты памяти на контейнеры (`mem_limit`), суммарно до 2 ГБ на проект.
  Логи `json-file`, `max-size: 20m`, `max-file: 3`.
- Бэкапы свои, в `/opt/<проект>/backups`, своим таймером. Бэкап MDM соседей
  не копирует.
- Секреты — в `.env` с правами 600, не в compose открытым текстом.

## 3. Как выйти наружу доменом

1. Веб-контейнер проекта публикует порт **только на loopback**:
   ```yaml
   ports:
     - "127.0.0.1:8089:80"
   ```
   Заняты: 80, 443, 8080 (MDM), 8088 (dos-mart). Свободны 8081–8087, 8089–8099.
2. Файл `/opt/edge/sites.d/<проект>.conf` по образцу из
   `/opt/edge/sites.d/README.md` (`server_name` домена, `proxy_pass` на свой
   порт), затем:
   ```bash
   docker compose -f /opt/edge/compose.yml exec nginx nginx -t
   docker compose -f /opt/edge/compose.yml exec nginx nginx -s reload
   curl -sI -H 'Host: <домен>' -H 'X-Forwarded-Proto: https' http://127.0.0.1/
   ```
   Нужен ответ приложения, не 404 от edge и не редирект.
3. Домен, DNS и сертификат заводит сетевик заказчика (Кирилл) на своём прокси
   и направляет имя на `192.168.1.5:80` — так же, как остальные. Больше от
   него ничего не нужно.
4. Приложение за edge:
   - схему берёт из `X-Forwarded-Proto`, а не из своего порта (иначе петля
     редиректов http→https, мы в неё уже попадали 26.09);
   - **не делает** свой редирект на https и не ставит HSTS — это делает прокси;
   - `X-Forwarded-For` доверяет только адресу edge (для контейнера это шлюз
     его docker-сети, обычно `172.x.0.1`); цепочка `клиент, 192.168.1.3`.

## 4. dos-mart: текущее состояние (10.10.2026)

Проект перенесён из `/home/ubuntu/dosmart` в `/opt/dosmart` (владелец `ubuntu`),
compose-файл `compose.onprem.yml`, запускается **только** так:
```bash
cd /opt/dosmart && docker compose --env-file .env.production -f compose.onprem.yml up -d web
```
(без `--env-file` compose падает на `DB_PASSWORD`). База и загрузки — в
именованных томах `dosmart_postgres_data` и `dosmart_uploads`, они переезд
пережили. Из compose убрана внешняя сеть `mdm_default`, порт
`127.0.0.1:8088:80` оставлен — на него смотрит edge. 503 на сайте — их
собственный режим обслуживания (`storage/framework/down`, `php artisan up`
снимает), к маршрутизации отношения не имеет.

## 5. Чего не делать

- Не трогать `/opt/mdm`, контейнеры `mdm_*`, порт 443 и ufw-правила MDM.
- Не ставить nginx/php/postgres на хост мимо Docker.
- Не перезагружать машину и Docker без согласования с владельцем MDM.
- Не публиковать порты на `0.0.0.0` или `192.168.1.5` — только 127.0.0.1,
  наружу ведёт edge.
